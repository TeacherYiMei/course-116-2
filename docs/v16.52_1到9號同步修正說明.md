# v16.52｜各班 1～9 號星星同步修正

## 根因（依 v16.51 原始碼與附帶 firestore.rules）
- `shared/store.js` 的 `STORE.login` 將學生座號從 `1` 改成 `01`。
- `firestore.rules` 對學生更新 `students/{uid}` 要求 `seatNo`、`className`、`name` 均與原文件相同。
- 已有舊文件若 `seatNo` 為 `1`，學生使用新入口登入後上傳 `01`，便會收到 `permission-denied`，包括整個進度寫入被拒。
- 舊 localStorage 鍵 `c116-11601-progress-902-1` 與新鍵 `...-902-01` 不同，導致既有本機進度在新版本中看似消失。

## 修正
- `shared/firebase-sync.js`: `saveStudent`、`saveCourseLevel`、`saveCourseSnapshot` 在已有紀錄時不更改姓名、班級和座號；先檢查該 UID 的班級／數值座號是否一致。**保留雲端 `seatNo` 原有格式**，不大量修改舊資料，不放寬 Firestore 權限。
- `shared/store.js`: 讀取 1～9 號進度時，額外讀取相同班級座號的舊 localStorage key，逐關採最高星數合併；不刪除舊鍵。

## 正式使用前的驗證（先備份 Firebase）
1. 比對 Firestore 正式部署的 security rules 是否與 ZIP 內相同；若不同，需另行檢查。
2. 以 902、903、909、910 每班 1 位舊版 1～9 號學生的 **原帳號及密碼** 登入，先確認原 `students/{uid}` 的 `seatNo`，並拍照或匯出星數。
3. 在第一單元取得測試成績，檢查 Firebase `students/{uid}/courseProgress.11601.modules.digital` 及教師版是否同步更新；再檢查 Python 的既有進度沒有下降。
4. 再各取 1 位 10 號以上學生回歸測試，避免改壞正常學生。
5. 如果還是 `permission-denied`，記錄 Firebase 錯誤、當前 UID、文件 `className/seatNo/name`；姓名不一致、UID 錯誤或部署規則不同仍可能拒絕。
6. 之前僅存在已清除瀏覽器 localStorage 的星星，若雲端與其他備份也找不到，修正程式無法恢復。

## 限制
本版本只經原始碼檢視與 JavaScript 語法檢查；未直接連線正式 Firebase，無法驗證所有 1～9 號學生的實際資料是否完整。請先在測試環境試行再全面發布。
